## Ответы на вопросы ТЗ
| Вопрос | Ответ |
|---|---|
| Нужен ли `-gamestateintegration` | **Нет.** Два полных матча записались без него. Первый вывод «нужен» был ошибкой: работали две копии рекордера, пакеты шли в первую, а смотрели вторую (исправлено: вторая копия теперь не запускается) |
| Когда начинаются пакеты | С загрузки матча (`WAIT_FOR_PLAYERS_TO_LOAD`). В главном меню пакетов нет. Частота около 1–1.5 пакета в секунду |
| Блок `roshan` (п. 5.3) | Всегда пустой `{}` |
| Смерть Рошана (п. 5.3) | **Есть событие** в `events`: `{"event_type": "roshan_killed", "killed_by_team": "radiant", "killer_player_id": 2, "game_time": 2098}` и следом `{"event_type": "aegis_picked_up", "player_id": 3, "snatched": false}`. Проверено только для убийства своей командой. Приходит ли событие, когда Рошана убивают враги, **пока не известно** |
| Терзатель | Отдельного события об убийстве нет. На миникарте (`minimap`) виден юнит `npc_dota_miniboss`, когда он в обзоре |
| Прочие события | `bounty_rune_pickup` (подбор баунти своей командой, с суммой), `chat_message` (сообщения игроков), `generic_event` с системными сообщениями чата: убийства, башни, бараки, байбеки, покупки, глиф, варды, курьеры |
| Особенность `events` | Одно и то же событие повторяется в нескольких пакетах подряд. Движку нужно убирать повторы (ключ: `event_type` + `game_time` + поля) |
| Блок `draft` (п. 6.1) | Всегда пустой `{}` в Turbo и All Pick. Вражеских пиков через GSI нет |
| Признак режима игры (п. 6.2) | **Нет.** `map.customgamename` пустой, других полей режима нет. `league` = 0 |
| `player.accountid` | Есть (32-битный id, подходит для OpenDota `/players/{id}`) |
| Горн | `game_state` переходит в `DOTA_GAMERULES_STATE_GAME_IN_PROGRESS` при `clock_time` = 0. До этого `PRE_GAME` с отрицательным `clock_time` |
| Время | `map.clock_time` = игровые часы (как на экране). `map.game_time` идёт с загрузки и больше на длительность драфта и подготовки. События используют `game_time` |
| Конец матча | `game_state` = `DOTA_GAMERULES_STATE_POST_GAME`, `map.win_team` = `radiant`/`dire` (во время игры `none`) |
| День/ночь | `map.daytime` (true/false), отдельно `map.nightstalker_night` |
| Пауза (`map.paused`) | **Есть** (запись gsi_2026-09-28_20-12-12.jsonl, игра с ботами, две паузы по 5–6 сек до горна). На паузе `paused` = true, `clock_time` и `game_time` стоят на месте. Пакеты во время паузы почти не приходят (нет изменений), поэтому таймеры считать только по игровым часам, не по часам компьютера |

## Принятые решения (28.09.2026, согласовано с автором)
1. `-gamestateintegration` не требуется. Проверку при запуске (п. 4.3 ТЗ) не показываем; параметр упоминается только как запасной вариант, если данные не идут.
2. Рошан: таймер запускается автоматически по событию `roshan_killed`, аегис по `aegis_picked_up`. `Ctrl+Alt+R` остаётся страховкой.
3. Терзатель: события нет, таймер повторного появления запускается клавишей `Ctrl+Alt+T`. Распознавание по экрану можно попробовать в фазе 3.
4. Вражеские герои: GSI их не отдаёт. Фаза 2: ручной выбор, фаза 3: распознавание по скриншоту верхней панели.
5. Режим игры: GSI его не отдаёт. Переключатель «Обычный / Турбо» в главном окне, последний выбор запоминается.

## Закрыто без проверки
- Приходит ли `roshan_killed`, когда Рошана убивают враги. Решили не проверять отдельно: игра объявляет убийство Рошана голосом обеим командам, и если события не будет, пользователь услышит диктора и нажмёт `Ctrl+Alt+R`.
