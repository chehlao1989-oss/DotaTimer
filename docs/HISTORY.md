## 1. Что за проект
Бесплатная программа-помощник для Dota 2 под Windows (Python, PySide6). Автор — игрок, Python на начальном уровне; код пишет агент.
- **Фаза 1 — таймеры** (руны, святилища, терзатель, день/ночь) с голосом, поверх игры. Данные только из GSI (официальный канал Valve). **Работает у автора.**
- **Фаза 2 — угрозы и советы по предметам.** Кто у врага опасен и что покупать против него. Враги — по снимку верхней панели экрана, их предметы — по клику на портрет. Никакого чтения памяти игры и скрытых данных.

## 2. Как устроены советы (спецификация автора v2, `docs/RECOMMENDER_SPEC.md`)
1. **Сбор** (GitHub Actions): сыгранные публичные матчи из Steam Web API — итоговые предметы, нетворс, длительность; ранги матчей из OpenDota. Храним **сырые матчи** (Parquet), считаем отдельно.
2. **Расчёт** (DuckDB): для моего героя H против врага E (или его предмета X) и каждого предмета Y:
   - **A — «берут чаще»**: насколько чаще игроки на H покупают Y, когда у врага есть X, чем когда нет (в п.п.);
   - **B — «выигрывают чаще»**: разность разностей винрейта (помогает ли Y именно против X);
   - сравнение внутри похожих игр: длительность × роль H по нетворсу;
   - сглаживание от точного к общему (E с X → любой враг с X → механика X), сила сглаживания подбирается по данным (эмпирический Байес);
   - оценка S = A/σ + B/σ; вето, если Y достоверно вредит.
3. **Кандидаты**: готовые предметы от 1000 золота, которые герой покупает хотя бы в 3% игр; либо механически отвечают врагу (15 правил механик, утверждены автором: «лечение → режет лечение», «уклонение → пробивает уклонение» и т.д.), либо в топ-5 по A («по опыту игроков»).
4. **Результат**: файл `recs.zip`, разложенный по героям — программа читает только кусок своего героя.

## 4. Решения вечера 30.09 (по цифрам)
**Порядок советов** — решение автора: «механика первой, только если A > 0». Опыт на 378 809 матчах:

| Порядок | Сверка с вики (достижимые пары) | Разных топ-3 у героя по врагам | Первые 2 совета с A ≤ 0 |
|---|---|---|---|
| по оценке S (исходная спека) | 58,5% | 73% | 9% |
| сначала механика всегда | 78,0% | 31% | 34% |
| механика первой при A > 0 | 70,2% | 61% | 7% |
| + широкие правила только при значимом A (итог) | 57,0% | 74% | 5% |

- Сверка с вики — проверка здравого смысла, а не цель: вики советует универсальные предметы, подгонка под неё делает советы одинаковыми (позиция автора).
- **Широкие правила механик** (критерий автора: признак у > 40% героев): «сильный контроль» 76%, «магический урон» 70%, «сильные пассивки» 47%, «мобильность» 45%. Ответ на них идёт «по механике» только при значимо положительном A.
- Правило работы: вопросы, решаемые цифрой, агент решает сам и записывает в DECISIONS; автору — только продуктовое.

## 5. Проверки качества советов
- **8.3 — искусственные матчи с известным ответом:** Vessel (адаптация) — A +40,0 п.п. при истинных +40; Skadi (эффект) — B +9,8 п.п. при истинных +15 (сглаживание занижает); BKB (чаще только в долгих играх) — A +1,7 и B +1,7 при истинных 0. Метод работает.
  Замечание: правило «A > 0 первым» ставит Skadi (помогает, но берут не чаще) после Vessel (берут чаще, но не помогает). Проверяется вариант «A > 0 или B значимо > 0».
- **8.2 — свежие данные** (отложены последние 3 часа матчей — 3 дня пока недоступны, см. ниже):

| | Совпадение знака, все советы с высокой уверенностью | Где значим на проверочной части |
|---|---|---|
| B (чаще выигрывают) | 53,8% | 60,1% (7 927) |
| A (чаще берут) | 66,8% | **84,6%** (11 750) |

  Вывод: A повторяется, B пока в основном шум. В оценке S = A/σ + λ·B/σ при λ = 1 шум B двигает порядок — λ будет выбран опытом.
- **Выборка:** все 378 809 матчей первого расчёта сыграны за ~10 часов одного дня (28.09 12:00–22:15 UTC): сборщик идёт по матчам подряд медленнее, чем они играются → смещение к регионам этого времени суток. Вариант — начинать каждый запуск с новой точки времени; решается замером.
