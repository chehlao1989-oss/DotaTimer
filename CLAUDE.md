# Инструкции для агента: проект «Dota таймер» (техническое имя DotaTimer)

Ты разрабатываешь программу-помощник для Dota 2 под Windows на Python. Требования: `docs/TZ.md`, статистика и советы — `docs/RECOMMENDER_SPEC.md`.
Порядок работы (обязательный, важнее прошлых договорённостей) и действующие решения:
@docs/PROCESS.md
@docs/DECISIONS.md

Словарь доты (как автор называет роли, руны, предметы и героев). Говори с автором на этом языке: «активка на 6:00», «тараска», «пятёрка».
@docs/GLOSSARY.md

## Кто пользователь
- Автор проекта, знает Python на начальном уровне, работает в PyCharm. Код пишешь ты, он проверяет результат в игре.
- **Общайся только на русском**, простыми словами. Дотерский сленг можно, программистский жаргон нельзя: если без термина не обойтись, поясни его в одной фразе. Кнопки GitHub и программ — с переводом и точным местом.
- Автор хорошо знает Доту. Игровые механики не объясняй, но проверяй с ним спорные игровые решения (что считать угрозой, какие контры советовать).
- После каждой завершённой задачи: что сделано; **как запустить в PyCharm** (пошагово); **как проверить** (если в игре — точный чек-лист). Проверки в игре копить в `docs/test_plan.md`, не просить катку ради мелочи.
- Фича, зависящая от игры, не готова, пока автор не подтвердил её в игре.

## Фазы
- Работай **строго по фазам** из `docs/TZ.md` (п. 12). Следующая фаза — только после приёмки текущей.
- Если ТЗ противоречит реальности, остановись, объясни варианты, после решения **обнови `docs/TZ.md`** и его «Историю изменений».

## Жёсткие запреты (иначе пользователей забанят)
Никогда, ни в каком виде, даже «для отладки»:
- не читать память `dota2.exe`, не внедряться в процесс, не перехватывать сетевой трафик игры;
- не получать данные идущего матча через Steam Web API (`GetRealtimeStats` и т.п.) или любые источники скрытой информации;
- не эмулировать нажатия клавиш и клики в игре;
- не смотреть профили и историю соперников во время драфта;
- не парсить Dotabuff.
Разрешено: GSI, скриншоты того, что видно на экране, ручной ввод, открытая статистика OpenDota/STRATZ. Если сомневаешься, спроси автора и объясни риск.

## Правила кода
- Python 3.12, зависимости только через `requirements.txt` (сборщик — `requirements-collector.txt`) и `.venv`. Новую библиотеку — только с объяснением, зачем она.
- Имена переменных, функций и файлов на английском. **Комментарии и docstring на русском.**
- **Все строки интерфейса и голосовые тексты — только в `app/i18n/ru.py`.**
- Названия героев и предметов на английском, как в игре (OpenDota constants), не переводить.
- **Никаких игровых чисел в коде.** Тайминги — `data/timings.json`, механики — `data/mechanics.json`, настройки расчёта — `data/recs_config.json`, угрозы — `data/threats.json`. У каждого игрового значения `source` (Liquipedia, dota2.com/patches, подтверждение автора) или `"verified": false`.
- Тяжёлые операции (сеть, распознавание) — не в потоке интерфейса.
- Настройки, кеш, логи — в `%APPDATA%\DotaTimer\`. Логирование через `logging`. Без интернета таймеры работают из кеша.

## Сборщик статистики
- После каждого запуска сбора — отчёт автору в 5 строк из `python tools/report.py`.
- Ключ Steam только в GitHub Secrets и `%APPDATA%\DotaTimer\steam_key.txt`; никогда не печатать и не класть в репозиторий.

## Тесты и git
- `pytest`; хук Claude Code запускает тесты перед `git commit` и блокирует коммит при падении (`.claude/hooks/pre_commit.py`).
- Записи матчей: `tools/gsi_recorder.py`, проигрывание `tools/gsi_replay.py` — **не проигрывать, пока запущена программа автора** (порт 53000, BUGLOG №17).
- Коммит после каждого законченного шага, сообщение на русском. Не коммитить `.venv`, кеш, логи, личные настройки, токены, скриншоты с чужими никами.

## Команды
- Установка: `python -m venv .venv` → `.venv\Scripts\activate` → `pip install -r requirements.txt`
- Запуск: `python -m app.main`; тесты: `pytest`
- Сводка по сбору: `python tools/report.py`; предпросмотр оверлея: `python tools/render_overlay_preview.py`
- Сборка (фаза 3): `pyinstaller` с конфигом из репозитория (onedir)
