# Инструкции для агента: проект «Dota таймер» (техническое имя DotaTimer)

Ты разрабатываешь программу-помощник для Dota 2 под Windows на Python. Полное техническое задание: `docs/TZ.md`. **Прочитай его целиком перед любой работой** и сверяйся с ним.

Словарь доты (как автор называет роли, руны, предметы и героев) подключён ниже. Говори с автором на этом языке: «активка на 6:00», «тараска», «пятёрка», а не «power rune spawn event».
@docs/GLOSSARY.md

## Кто пользователь
- Автор проекта, знает Python на начальном уровне, работает в PyCharm. Код пишешь ты, он проверяет результат в игре.
- **Общайся только на русском**, простыми словами. Дотерский сленг можно, программистский жаргон нельзя: если без программистского термина не обойтись, поясни его в одной фразе.
- Автор хорошо знает Доту. Игровые механики ему не объясняй, но проверяй с ним спорные игровые решения (что считать угрозой, какие контры советовать).
- После каждой завершённой задачи коротко напиши:
  1. что сделано (2–4 пункта);
  2. **как запустить в PyCharm** (пошагово: какой файл, какая кнопка, что поставить);
  3. **как проверить** (что должно произойти; если нужна проверка в игре, опиши точно, что сделать в Доте).
- Когда нужен тест в реальной игре, попроси об этом явно и дай чек-лист. Не считай фичу готовой, пока пользователь не подтвердил, что она работает в игре (если фича зависит от игры).

## Порядок работы
- Работай **строго по фазам** из `docs/TZ.md` (п. 12). Не начинай следующую фазу, пока текущая не принята пользователем.
- Перед началом фазы дай короткий план (5–10 пунктов) и задай вопросы, если что-то неясно. Мелкие технические решения принимай сам.
- Большие изменения делай небольшими шагами, каждый шаг должен запускаться.
- Если выясняется, что ТЗ противоречит реальности (например, GSI не отдаёт нужное поле), остановись, объясни пользователю варианты, а после решения **обнови `docs/TZ.md`** и отметь это в разделе «История изменений» в конце ТЗ.

## Жёсткие запреты (иначе пользователей забанят)
Никогда, ни в каком виде, даже «для отладки»:
- не читать память `dota2.exe`, не внедряться в процесс, не перехватывать сетевой трафик игры;
- не получать данные идущего матча через Steam Web API (`GetRealtimeStats` и т.п.) или любые источники скрытой информации;
- не эмулировать нажатия клавиш и клики в игре;
- не смотреть профили и историю соперников во время драфта;
- не парсить Dotabuff.
Разрешено: GSI, скриншоты того, что видно на экране, ручной ввод, открытая статистика OpenDota/STRATZ. Если сомневаешься, спроси пользователя и объясни риск.

## Правила кода
- Python 3.12, зависимости только через `requirements.txt` и виртуальное окружение `.venv`. Новую библиотеку добавляй только с объяснением, зачем она нужна.
- Имена переменных, функций и файлов на английском. **Комментарии и docstring на русском.**
- **Все строки интерфейса и голосовые тексты хранятся только в `app/i18n/ru.py`.** В коде интерфейса нет русских строк напрямую.
- Названия героев и предметов на английском, как в игре (берутся из OpenDota constants), не переводить.
- **Никаких игровых чисел в коде.** Тайминги лежат в `data/timings.json`, контры в `data/counters.json`, веса угроз в конфиге.
- Игровые данные не выдумывать. Каждое значение в `timings.json` и `counters.json` сверять с Liquipedia или dota2.com/patches и указывать `source` и `checked_patch`. Если проверить не удалось, пометить `"verified": false` и сказать пользователю.
- Тяжёлые операции (сеть, распознавание) выполнять не в потоке интерфейса. Интерфейс не должен подвисать.
- Настройки пользователя, кеш и логи хранятся в `%APPDATA%\DotaTimer\`, не рядом с программой.
- Логирование через модуль `logging`: при ошибке пользователь присылает лог-файл.
- Ошибки сети и отсутствие интернета не должны ломать таймеры, программа работает из кеша.

## Тесты
- `pytest`. Движок таймеров, менеджер уведомлений (склейка, антиспам, приоритеты) и оценка угроз обязаны иметь тесты.
- Для тестов используй записи реальных матчей из `tools/gsi_recorder.py` и проигрывай их через `tools/gsi_replay.py`. Так программу можно проверять без запуска Доты.
- Перед каждым коммитом тесты должны проходить.

## Git
- Коммит после каждого законченного шага, сообщение на русском: «Таймеры: склейка событий в окне 5 сек».
- Не коммитить `.venv`, кеш, логи, личные настройки и токены (STRATZ-токен только в настройках пользователя).

## Команды
- Установка: `python -m venv .venv` → `.venv\Scripts\activate` → `pip install -r requirements.txt`
- Запуск: `python -m app.main`
- Тесты: `pytest`
- Запись матча: `python tools/gsi_recorder.py`
- Сборка (фаза 3): `pyinstaller` с конфигом из репозитория (onedir)

Начни с **фазы 0** из `docs/TZ.md`: создай структуру проекта, `requirements.txt`, `.gitignore`, `README.md`, GSI-рекордер и инструкцию пользователю, как записать 2 матча.
